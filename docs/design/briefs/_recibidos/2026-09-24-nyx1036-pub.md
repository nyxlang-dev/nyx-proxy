El toolchain instalado (`~/.nyx`, main `7b45deee` del lenguaje) arregló un bug del resolvedor:
lo que un módulo declaraba después de un import transitivo se atribuía al archivo principal, y
eso ocultaba NYX1036 (llamar desde otro módulo a una fn sin `pub`). Con el arreglo, esos casos
salen como AVISO durante una transición; en la próxima versión menor del lenguaje pasan a ser
ERROR y los tests del proxy dejarían de compilar.

En este repo hay 76 avisos, todos en tests, sobre 8 fns privadas de `src/router`:
`pool_init` (23), `forward_pooled` (21), `pool_len` (13), `forward_pooled_c` (10),
`sse_tunnel` (5), `upstream_set_close_timeout` (2), `read_upstream_response` (1), `pool_get` (1),
en `tests/test_proxy_pool_framing.nx` (40), `test_proxy_sse_tunnel.nx` (27),
`test_proxy_retry.nx` (5), `test_proxy_sse_tls.nx` (3), `test_proxy_time.nx` (1).

Qué hacer: decidir por fn si agregar `pub` (es API que los tests usan con razón) o si el test
debe ir por la API pública. Después: `nyx check` de cada test sin avisos NYX1036,
`make test-proxy` en verde, commit atómico y actualizar el estado del repo según sus reglas.

Opcional: `[lib] modules` en `nyx.toml` ya funciona con cualquier forma de import
(compilación separada; ver `LLM.md` §10.1 del toolchain).

## Report — 2026-09-24

**Hecho: las 8 fns pasan a `pub`.** Ninguna se reescribió por la API pública.

Por qué, fn por fn:

- `pool_init`, `pool_len`, `pool_get` — el invariante que protegen los tests es que un fd solo
  vuelve al pool con el cuerpo leído entero (RFC 9112 §6.3, el bug de `104d400`). La única
  forma de *medirlo* es mirar el pool: por `proxy_dispatch` el test vería respuestas correctas y
  pasaría en verde sobre un pool corrupto (la regla de AGENTS.md §Tests: forma vs. valor).
  `pool_len` ya estaba comentada como «tests y diagnóstico».
- `forward_pooled`, `forward_pooled_c`, `read_upstream_response` — son la costura del encuadre.
  Cada caso usa un índice de upstream propio para no compartir pool; por `proxy_dispatch` habría
  que armar config y vhosts por caso y se perdería ese aislamiento.
- `upstream_set_close_timeout` — es un setter de configuración, hermano de
  `sse_set_max_tunnels`, que ya era `pub`. Es API legítima.
- `sse_tunnel` — los casos del túnel miden que la pausa del upstream se preserve sobre un fd
  controlado por el test; eso no se puede observar desde afuera del router.

En `src/router.nx` quedó un comentario que marca estas fns como superficie de test y
diagnóstico, no como API estable del consumer.

Evidencia:

- `nyx check` (0.33.0) sobre las 9 suites y `examples/standalone.nx`: 0 avisos, rc 0.
- `make test-proxy` con un `NYX_HOME` aislado (copia de `nyx_bootstrap`, `runtime/` y `std/` de
  `~/.nyx`, para no tocar el `script.nx` compartido): 9 suites ok, 0 fail.

`[lib] modules`: no se adoptó en este encargo; queda anotado como opción.
